# OPT-004 - Scope Verification Cost To What Actually Changed

## Goal

Stop verification cost from being driven by the workflow mode name, so a release, packaging, or
documentation task that changes no executable behavior no longer declares a test mode or re-runs a
suite whose inputs have not changed.

## Context Budget

Required:

- Applicable `AGENTS.md`
- `docs/ai/PROJECT.md`
- `docs/ai/STATE.md`
- This task card
- `docs/ai/tasks/RELEASE-002.md` as the observed case

Read if needed:

- `skills/project-dev/references/testing-strategy.md`
- `skills/project-dev/scripts/check_project_state.py`

Do not read by default:

- All historical task cards
- Generated release archives under `dist/`

## Scope

Allowed:

- `skills/project-dev/` — impact classification, testing strategy, workflow modes, `SKILL.md`, tests.
- `README.md`, `CHANGELOG.md`, `docs/` — documentation of the corrected policy.

Forbidden:

- `dist/` release archives.
- Weakening any check: a behavior change must still declare a test mode, and a required TDD policy must still bind behavior impacts.

## Acceptance Criteria

- [x] A release-style card with `impacts` containing `operations` may declare `test_mode: none` without error.
- [x] Other executable impacts (`domain`, `data`, `api`, `security_privacy`, `ui`, `dependencies`, `architecture`) still forbid `test_mode: none`.
- [x] `operations` alone no longer forces a `tdd_policy: required` project into `tdd` or `mixed`.
- [x] A behavior impact still honours a `tdd_policy: required` project.
- [x] `testing-strategy.md` states that verification cost follows the change, and that unchanged inputs must not be re-run.
- [x] `workflow-modes.md` no longer instructs a standard task to run focused tests unconditionally.
- [x] `SKILL.md` states the no-executable-change rule at the point of mode and check selection.
- [x] All pre-existing tests still pass unchanged.

## Required Checks

- `python -B -m unittest discover -s skills/project-dev/tests -p "test_*.py" -v`
- `python <skill-dir>/scripts/check_project_state.py --project <repo> --strict`

## Red Evidence

- Not applicable: `tdd_red_verified` is false. The rule change and its regression tests were produced together, not test-first.

## Delivery Evidence

- `python -B -m unittest discover -s skills/project-dev/tests -p "test_*.py"` reported `Ran 34 tests ... OK` (30 pre-existing, 4 new).
- `python skills/project-dev/scripts/check_project_state.py --project . --strict` reported `[OK] errors=0 warnings=0` for this repository.
- Observed cause, recorded for the next session: `RELEASE-002.md` declared `impacts: ["documentation", "operations", "delivery_status"]`, so `operations` being executable forced `test_mode: test-after`, and its `Required Checks` listed the full unit suite, which then ran on unchanged code.
- `EXECUTABLE_IMPACTS` now excludes `operations`, with the reasoning recorded beside the definition.

## Remaining Risks

- An operations change that alters deploy or packaging *logic* no longer forces a test mode. `test_reason` remains mandatory, and release risk is carried by artifact verification and authorization, but a reviewer must still judge that case.
- The rule is now stated in four places; a future edit to the policy must update them together.
