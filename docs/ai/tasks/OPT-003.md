# OPT-003 - Reconcile Coordination Records With The Repository

## Goal

Make the coordination records verifiable against the repository, so a session that drifts
in scope, records the wrong branch, or claims unverified work is detected instead of
silently trusted by the next session.

## Context Budget

Required:

- Applicable `AGENTS.md`
- `docs/ai/PROJECT.md`
- `docs/ai/STATE.md`
- This task card
- Sections listed in `design_refs`

Read if needed:

- `skills/project-dev/scripts/check_project_state.py` and its test suite

Do not read by default:

- All historical task cards
- Generated release archives under `dist/`

## Scope

Allowed:

- `skills/project-dev/` — validator, tests, task template, and `SKILL.md` routing.
- `README.md`, `CHANGELOG.md`, `docs/` — documentation of the new behaviour.

Forbidden:

- `dist/` release archives, which are generated from committed source at release time.
- Weakening the existing protected-path, conflict, dependency, or design-sync checks.

## Acceptance Criteria

- [x] A recorded branch that is not the checked-out branch is detected: error while a task is active, warning while idle.
- [x] An active card that has started but whose `branch` is not checked out is an error, while a `ready` card may name a branch that does not exist yet.
- [x] Changes inside `forbidden_paths` are errors; changes outside `allowed_paths` are warnings.
- [x] The coordination tree under `docs/ai/` is excluded, and a repository with no baseline commit skips scope checking.
- [x] `tdd_red_verified: true` without a recorded Red command and failure result warns.
- [x] `checks_complete: true` whose delivery evidence shows no command warns.
- [x] `--brief` prints a digest containing the active task, its scope, and a branch-mismatch marker.
- [x] All pre-existing tests still pass unchanged.

## Required Checks

- `python -B -m unittest discover -s skills/project-dev/tests -p "test_*.py" -v`
- `python <skill-dir>/scripts/check_project_state.py --project <repo> --strict`
- `python <skill-dir>/scripts/check_project_state.py --project <repo> --brief`

## Red Evidence

- Not applicable: `tdd_red_verified` is false. Regression tests were written after the validator changed, not before it.

## Delivery Evidence

- Implementation: three gates and a digest added to `check_project_state.py`; `matches_protected_pattern` refactored onto a shared `matches_path_pattern`.
- `python -B -m unittest discover -s skills/project-dev/tests -p "test_*.py"` reported `Ran 29 tests ... OK` (20 pre-existing, 9 new).
- `python skills/project-dev/scripts/check_project_state.py --project . --strict` reported `[OK] errors=0 warnings=0` for this repository.
- `--brief` verified against this repository and against test fixtures, including the mismatch marker.

## Remaining Risks

- The scope gate compares against the card's `base_branch`, so a card with an unrealistically narrow `allowed_paths` produces warnings until the card is corrected; this is intended but may feel noisy at first.
- Evidence binding checks for a recorded command and a failure marker. It cannot prove a claimed command was actually run, only that none was recorded at all.
