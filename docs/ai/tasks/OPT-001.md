# OPT-001 - Add Adaptive Low-Overhead Delivery Modes

## Goal

Make ordinary AI development materially faster by applying only the workflow rigor justified by task risk while retaining safe recovery after any session switch.

## Scope

Allowed:

- Add `fast`, `standard`, and `strict` workflow routing.
- Allow recoverable inline fast work without a separate task card or branch.
- Make design synchronization explicit rather than automatic for every behavior impact.
- Reduce redundant state transitions, checks, narration, and test runs.
- Keep existing v1 project files valid.

Forbidden:

- Weakening protected path, Git conflict, secret, destructive action, or remote authorization rules.
- Removing task cards and branches from high-risk work.
- Making TDD mandatory for ordinary implementation.

## Acceptance Criteria

- [ ] Low-risk single-session work can use inline state on the default branch without a task card.
- [ ] A new session can recover inline work from state and Git differences.
- [ ] Standard work uses one task card, one short branch, focused checks, and end-only documentation updates when design actually changes.
- [ ] Strict mode remains mandatory for high-risk changes.
- [ ] Existing v1 project state and cards remain valid.
- [ ] TDD evidence remains enforced when TDD or mixed mode is selected.

## Required Checks

- `python -B -m unittest discover -s skills/project-dev/tests -p "test_*.py" -v`
- Official Skill validation for both Skill folders.
- `python -B skills/project-dev/scripts/check_project_state.py --project . --strict`
- Review installed Skill copies against committed source.

## Delivery Evidence

- Red: new inline fast-state and explicit design-sync tests failed against the v1 checker for the intended missing behavior.
- Green: all 20 state, adaptive workflow, TDD, Git, protected-path, and baseline tests passed.
- Both Skill directories passed the official `skill-creator` validator.
- `check_project_state.py --strict` passed on this repository.
- Scenario review confirmed copy/style routes to fast, ordinary multi-file work routes to standard, and data/security/release work routes to strict.
- Existing v1 fixtures remained valid without adding adaptive fields.

## Remaining Risks

- Risk classification remains a judgment call; project policy can set `workflow_policy: standard` or `strict` to prevent unsafe downgrades.
- The reduced workflow should be tuned from real usage evidence rather than additional speculative rules.
